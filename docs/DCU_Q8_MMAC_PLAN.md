# Q8 投影改为 gfx936 MMAC 小矩阵乘法

## 决策

重写 Q8 投影执行路径：专用分块权重格式、INT8 MMAC、计算维分段及合并、投影组接口。
允许改动加载器、权重描述、输入量化输出、矩阵执行和预填充权重读取；不以维持现有指针接口或线程分工为目标。
第一批覆盖 GDN QKV/门控/输出、QSA Q/输出和词表输出头，重点为2–5个验证位置。

以下原型结果与接入计划记录于 2026-10-25；当时尚未接入完整引擎。
后续接入及验证见本文末尾，原型算子速度不代表端到端收益。
原始记录保存在本地 `profile_output/q8-rewrite-plan-20261025/`，不随源码提交。

## 为什么选这条路线

当前 `native_mmvq_wave_kernel` 固定一条wave处理一行，逐块整数点积后进行wave内归约。
Q8单位置已接近读取限制，多位置的计算、输入访问和归约成本明显增加。
上轮修复原生dot4及连续读取只改善部分宽度，不能改变这个计算组织。

本机DTK的标准AMD MFMA INT8/FP16调用因缺少`mai-insts`被拒绝，但Hygon的MMAC调用可运行：
`__builtin_amdgcn_mmac_i32_16x16x32i8`生成实际`v_mmac_i32_16x16x32_i8`指令。
FP16 MMAC全1见证通过；本方案使用INT8路线。
INT8见证恢复全部256个输出的排列，随后64组随机输入共16384个输出对照独立CPU整数参考通过，包含负数和累加回绕。

wave64的输入片：A每lane8字节，行`lane%16`，计算维偏移`(lane/16)*8`；B同样每lane8字节，对应列`lane%16`。
每lane返回4个整数，输出行为`lane%16`，输出列为`lane/16 + 4*j`（j=0..3）。
因此一条wave同时算16行；四位置时每个lane都有一个有效输出，不需要旧路径的全wave求和树。

## 量化处理：以32个值为计算单位

Q8_0每32个值具有独立缩放。MMAC的计算维恰好为32：每次先得到该组的精确整数点积，
再乘对应权重行和输入位置的缩放，累加到FP32输出。
不能把整条2560维先做整数累加，再仅乘一次缩放。
新顺序相对旧实现允许FP32舍入差异，参考为同一量化数据的FP64点积；不要求旧输出逐位一致。

## 执行格式

权重变为：

```
Wq[k32_group][output_tile16][lane64][8 int8]
Wd[k32_group][output_tile16][16 fp16]
```

32个值的原始INT8编码和FP16缩放保持不变，不重新量化。
主模型所测五类矩阵输出行均为16的倍数，重新排列的字节数与原Q8_0相同；其他形状尾行补零并计入账单。
输入量化最终直接产生MMAC所需的输入片和缩放，省去每个投影内重复转换。

`NativeDense`和输出头使用带布局描述的权重对象，不继续依赖“所有设备指针都是GGUF块格式”的假设。
加载时直接创建执行布局；常驻GPU不保留完整的旧、新两套权重。
预填充的还原函数直接读取新布局并写到可复用工作区；临时还原权重也核算显存。
CPU专家的INT4格式独立。8500/8300专家数与全部GPU权重<=50%规则继续作为运行条件。

## 内核结构

1. 每wave16个输出行，首个原型每block4个wave，产生64行和1–5个位置。
2. 沿32值量化组执行MMAC，各输出FP32累计；按上述lane映射直接写输出。
3. 输出行少时把计算维分给4/8/16组block，各组写独立部分结果，再用一个归约内核合并。
4. 输出头行数大，已有足够block，优先不分段。分段需要额外工作区，选择依据为总延迟，包括归约。
5. 进一步加入寄存器预取或分块LDS双缓冲。改变32/64/128输出行块和计算维块，并按实际资源使用选择。
   当前设备每block LDS上限65536B；候选必须检查实际寄存器/溢出和可驻留block数量。

原型中的初版直接MMAC在6144→2560上仅40个block，80个CU无法铺满，且每块串行处理192个量化组；
1–3位置实测约153us、四位置约87.5us，明显慢于旧路径。计算维分段后缩短到约20–26us。
这说明本方案必须同时重做并行组织，不能仅替换一条指令。

## 真机原型结果

生产基准为当前部署版本的`native_mmvq`，静态库链接自同一构建目录。
使用模型实际矩阵尺寸、合成Q8权重和量化输入，轮换多个矩阵副本避免全部命中8MiB L2。
各比较单元旧/新使用相同数据，5轮交替次序，每轮重放30次GPU graph；事件计时含新路径的部分结果合并。
权重准备和分配不计入decode算子延迟；这些成本在载入阶段单独考虑。

四个位置的探索结果（微秒；下表配置从本轮候选中选取，尚非独立保留集验证）：

| 矩阵 | 当前实现 | MMAC方案 | 速度比 | 计算维分段数 |
|---|---:|---:|---:|---:|
| QKV 2560→10240 |61.84|32.74|1.89x|8|
| 门控2560→6144 |40.08|20.37|1.97x|4|
| 输出6144→2560 |39.10|20.53|1.90x|8|
| Q投影2560→12288 |72.97|38.14|1.91x|4|
| 输出头2560→248320 |1338.49|710.67|1.88x|1|

五位置输出头1569.35→751.59us，2.09x。
两位置的大投影约1.03–1.19x，三位置约1.30–1.52x；单位置的大投影目前仍比旧实现慢约10–27%。
因此需要单位置专用向量实现读取同一新布局，或在显存账单允许的探索阶段比较不同执行布局；
不能把本轮MMAC实现直接用于全部位置数。最终分发按形状与位置数预选，避免每token试跑调参。

所有5种尺寸×5种位置数均检查完整输出相对当前算子的误差，以及每位置32行对FP64参考的误差。
1/4/8/16分段均通过；图重放另外用NaN填充输出/工作区后验证，覆盖旧/新两种graph，共200个图检查。
数值范围是本轮种子与合成输入的证据，不能代替模型回答QA。

## 接入顺序

1. 建立新的Q8权重对象、分块载入和输入片量化，完成完整矩阵核心与分段合并。
2. 接入GDN投影组：同一输入的QKV与门控在行维组成一个2560→16384逻辑矩阵，直接写两个输出视图。
   QSA的Q/K/V可用同一投影组接口。投影组不产生额外拼接复制。
3. 更新预填充还原读取、主输出头与MTP输出头、显存账单和graph捕获；为单位置实现同布局向量内核。
4. 先用实际调用宽度分布加权的算子延迟和真实短链筛选。短链重现生产的量化、分支、事件等待、投影和消费者；
   合并投影会改变原有侧流并行，必须测完整短链，不能把两个独立GEMV耗时直接相加作为收益。
5. 方案定型后再跑完整回答/代码QA和少量端到端测速。当前不把约1.9x算子速度写成推理速度收益。

首轮性能目标：3–5位置的大矩阵加权耗时至少降低30%，对应短链至少降低15%；
单位置吞吐保持，再扩大适用矩阵。上述是实施目标，不是已获得的全引擎结果。

## 稳定验证窗口的可选路径（2026-11-03）

当前引擎可用 `STRATA_Q8_MMAC=1` 显式开启 MMAC。原型路径保留：大投影单位置走原 Q8 kernel，
多个验证位置使用按 T 选择的 split-K。它通过了本轮 18 项语义检查，但同一 seed 的两次采样在
第 22 个 token 分叉。独立 GPU 检查确认同一输入前缀在 T=1–5 时会出现浮点末位差异。

`STRATA_Q8_MMAC_STABLE=1` 另外选择一致路径：每种矩阵形状使用固定 split，单位置也走 MMAC。
它只在 MMAC 本身开启时生效；两个选项在普通源码中均需显式开启，未改变关闭时的执行路径。
这项选项用于跨验证窗口的同 seed 复现，不要求与原 Q8 算子逐位相同，也不把逐位一致当作模型质量指标。
只看语义 QA 的实验可以保留原调优切分，但应记录其采样复现限制。

验证使用同一 BW/gfx936、DTK26.04、32 CPU / 121.5 GiB 容器中的 GPU0：

- 6 种矩阵形状，含完整 248320 行输出头，T=1–5、每宽度两次 graph 重放。
  2821120 次前缀浮点比较由 194841 处不一致变为 0；相对原 Q8 算子的误差最大约 1.81e-7。
- 重新编译 HIP 引擎后，18 项语义检查、固定 seed、STOP/恢复、单 token 和上下文边界检查通过。
  QA 驱动现对 seed 不复现硬性报错，避免只打印 False 后仍输出 PASS。
- 独立检查者按实际公开入口运行一次，核对引擎摘要、133 个矩阵注册、实际 MMAC 派发及权重账单，通过。
  本轮未运行其他后端硬件或完整模型能力基准。

同一新二进制、GPU0、12 workers 加主线程、8500 GPU 专家、Q8 dense/head、HC Q8、调优 MTP、
IQ4_NL PLE、context512、INT8 KV、adaptive/maxT5。每配置独立启动一次，预热 128 tokens，

## 单份执行权重（2026-11-03）

`ExecutionWeight` 将 GGUF 量化类型与设备布局分开描述，记录矩阵尺寸、设备数据、
权重字节和归约工作区。它是借用视图；`NativeDense` / `NativeHead` 持有分配，
必须在所有可能执行的 graph 结束使用后才释放；释放后不得重放旧图。
启动时选定布局，token 路径不分配或转换整份权重。

开启 `STRATA_Q8_MMAC=1` 时，支持的 Q8 投影直接从主机 GGUF 排列为唯一的 MMAC 设备副本。
原来的 canonical-pointer → MMAC-copy 全局表已移除。`STRATA_Q8_PACKED=1` 不再为这些矩阵另建副本。
不支持的矩阵仍使用 GGUF 布局；PLE key 的专用接口明确保留 GGUF 布局。

单位置、验证窗口与共享专家使用带布局的 MMVQ 接口。T=6–8 以及非 stable 模式的
小矩阵单位置使用读取同一 MMAC 布局的向量内核，不依赖隐藏的旧权重。
`STRATA_Q8_MMAC_STABLE=1` 保留 T=1–5 的原有固定分段策略。

prefill 从执行布局直接反量化到原有有界行块工作区，也支持带 padding 的输出行。
MTP 子词表抽行重建原始 Q8_0 编码和 FP16 scale，不反量化再量化，不还原完整输出头。
完整输出头的 MTP 和 draft proxy 也读取该执行视图；BF16 DFlash 接口仍明确只取 GGUF 数据。
`NativeHead::weights()` 对非 GGUF 布局返回空，避免新的调用者把执行字节误当连续 GGUF 行。

可构建的检查目标：

```bash
cmake --build <hip-build> --target q8_execution_weight_test -j4
STRATA_Q8_MMAC=1 STRATA_Q8_MMAC_STABLE=1 <hip-build>/q8_execution_weight_test --require-stable
STRATA_Q8_MMAC=1 STRATA_Q8_MMAC_STABLE=0 <hip-build>/q8_execution_weight_test
```

检查包含七种尺寸（完整词表与非 16 对齐尾行）、T=1–8、每宽度两次 graph 重放，
以及切片 FP16 反量化、原编码抽行和 width2560 的 proxy 打包/重评分。
数值参考在释放旧 GGUF 设备副本前生成；所有后续矩阵执行都只剩新布局。
性能、实际显存和模型 QA 的记录必须与具体节点/二进制绑定，不能用这个检查代替。

向量回退使用相邻 lane 读取相邻 MMAC 权重片，四个 lane 合算一行，保留原始量化组缩放。
单位置速度取决于尺寸；热 graph 微基准中部分尺寸仍慢于 GGUF 路径，不承诺所有形状都有加速。
该阶段完成执行权重统一；同输入投影组、跨算子融合与共享工作区调度仍属于后续工作。
