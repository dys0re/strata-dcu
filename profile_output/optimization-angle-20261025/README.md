## 要改的算式

Q4_0 保存的 nibble 为 `u=0..15`，实际带符号整数为 `u-8`，输入 Q8 为 `y`。

现有内核每次处理一行权重，都先做 `u-8`、取绝对值、调整输入符号，
并对输入为 -128 的情况额外修正，才能使用无符号乘有符号的点积指令。

候选实现直接计算 `sum(u*y) - 8*sum(y)`。
其中 `8*sum(y)` 按输入的每4个元素先算好，每行权重复用；缩放、浮点累加顺序和输出处理保持现有实现。
这样省去每行反复做符号转换、绝对值及 -128 特殊修正。原型位于独立文件，未替换生产对象。
输入修正的准备时间已经包含在微基准计时内；没有提前移出计时来虚构收益。

## 独立实测

同一台主机、一个自动选出的空闲核心、Release 优化和实际启用的 AVX-512 VL/BW/VNNI 指令。
矩阵为真实模型形状：gate/up各640行×2560，down为2560行×640，Q4_0权重和Q8_0输入。
基线直接链接当前构建的 ggml/CPU 库；候选为独立编译，不重编生产引擎。

每项9轮，三种方法轮换执行顺序，保留每轮原始时间。
既测单份权重，也测轮换64份矩阵：gate/up共112.5MiB，down共56.25MiB，
大于所选核心的16MiB末级缓存。权重由正常量化器生成，64份为相同数值的独立物理数组。
没有声称复现完整真实专家访问分布或12线程内存争用。

轮换64份矩阵的单位置结果，单位微秒：

| 计算 | 当前实际路径：ggml逐行 | 现有融合内核直接用于单位置 | 输入修正复用原型 |
|---|---:|---:|---:|
| gate/up合并 | 241.02 | 239.45 | 226.95 |
| down | 142.54 | 128.00 | 116.34 |

两项独立计时中位数之和从383.56降到343.29，少约10.5%。
这是三次矩阵计算的合计，**不含中间量化、线程池、GPU或完整专家端到端计时**。
单份热权重下约为382.72→343.86，方向相同。
只把旧融合内核用于单位置，不能替代这里的算式改动：gate/up收益很小。

在两个到四个位置的现有融合路径上，候选的两阶段中位数之和减少约3.5%/2.3%/2.0%。
因此主要接入价值在单位置路径，不能把单位置收益推广成所有 CPU 专家均快10.5%。
热权重还测试了gate/up 32行、down128行的小任务分片，所有原始值均保留。

数值检查共48组，覆盖1–4个位置、完整矩阵与小分片，以及显式包含-128的Q8输入。
相对现有融合内核，实测输出差为0；普通输入相对ggml也为0；所有结果有限，退出码0。
这只证明这些模型形状和输入用例，不能代替完整量化格式或真实回答QA。
