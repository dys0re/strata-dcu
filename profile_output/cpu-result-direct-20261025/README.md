# CPU 专家输出直接合并：接入与验收

已将[独立原型](../cpu-gpu-handoff-20261025/README.md)接入引擎，开关为
`STRATA_CPU_RESULT_DIRECT=1`。**质量检查通过，但本轮没有建立整体 decode 收益，默认关闭。**

2026-10-25，SCNet BW/gfx936，运行环境沿用 `dflash2@52f8bc84`，没有安装或升级依赖。
旧版为 `226e785e` 的已部署二进制，SHA256
`4fc8304ec17c7e6b0df4a843f7f60ebe21934e6a7e88004a358e6b2356edb8cd`。
新版 SHA256 为
`81f79177f7e9b15a1d4506bed0211db95b369594868f51bcc19e64fa4017ce9b`。

## 实际改动

旧流程依次等待 CPU、把专家输出拷入显存临时区、加入 GPU 专家输出，再进行加权合并。
新算子直接从映射的主机内存读取 CPU 输出，从 GPU 输出区读取 GPU 专家结果，并完成加权合并。
保留 FP32、原专家顺序、第一项独立乘法和后续显式 FMA；GPU 行保留原来的 `0.0f + hit`。
临时缓冲区仍为回退保留；省去的是该阶段的读写，没有宣称释放它的分配。

CPU 的完成信号、第一层 PLE 完成条件、下一层路由与主机输出复用的先后关系均保留。
共享专家侧流完成后才启动直接合并。没有增加 GPU 模型权重副本，没有改变路由或专家缓存。

当前只为 `STRATA_HIP_GFX906` 兼容构建启用分发，覆盖单 GPU 原生专家、K=10、
对齐的 FP32 输出、每组1–8个位置。设备自行规划跳过 CPU、全常驻图、多 GPU、远端专家、
旧的 VERIFY_PROFILE 和分流成本记录等不满足条件时保留原流程。
公开说明及启闭命令见 [DCU_CPU_RESULT_DIRECT.md](../../docs/DCU_CPU_RESULT_DIRECT.md)。

## 正常速度与回答质量

执行顺序固定为旧 A→新 B→新 B2→旧 A2，四次冷启动。
每次先预热128tokens，再将英文故事、中文解释、Python代码各生成256tokens，重复三次；
随后执行18项回答/格式/代码执行QA，以及单token、上下文尾部、STOP/恢复。
四次均退出0且全部QA通过。没有把长输出token相同作为通过条件。

全部使用增强MTP adaptive/max T=5、Q8非专家矩阵和HC、蒸馏MTP、CPU Q4输入修正、
GPU常驻专家先运行、CPU专家流水与结果提前发布。固定8500 GPU专家、16076 RAM专家，
12个workers加主线程、512上下文、INT8 KV、持久盘PLE。
全部GPU权重均为29373360352B，小于34351349760B的半显存上限，包含临时专家槽。
没有扫描专家数或量化格式。正式运行没有全层标记、旧VERIFY_PROFILE或logits导出。

模型载入后采用已有空闲选核方法；四次均沿用节点3的
`48,50,51,52,53,54,55,56,57,58,60,62,63`。
四次启动采样最大忙占比分别0.33%、1.67%、2.33%、1.34%；正式请求最大逐线程排队占比0.75%。
这是共享CPU上的选核，不构成独占，没有改变生产选核，也未显式迁移权重页。

每轮三次的中位数，单位TPS：

| 旧 A | 36.54 | 47.41 | 58.12 |
| 新 B | 33.59 | 41.56 | 50.80 |
| 新 B2 | 36.67 | 46.22 | 60.96 |

三项比值的几何平均为0.9981358，约−0.19%。这是描述性结果，没有统计显著性或普遍提速声明。
保留每次结果、波动、请求、线程计数及NUMA快照，见四个运行子目录与 `analysis.json`。

预先记录的默认选择要求为合并结果几何平均至少1.01、且任一任务比值不低于0.97，
并通过完整质量检查。本轮未满足前者，因此只保留显式选项。
没有在看到结果后改变规则、关闭增强MTP、固定更有利的候选长度或提高GPU专家数。

CPU专家调用耗时也有明显波动。例如三次代码请求的CPU毫秒/窗口中位数：
旧A25.96、新B35.75、新B2 26.42、旧A2 37.64。
英文/中文的MTP窗口长度也变化。因此不能把全部速度差异归因于新算子的等待方式，
也不能把原型里十几微秒的局部节省说成已兑现的应用收益。
本轮未另做单独改变轮询线程数量的实验，没有确证其为退步原因。
