# 层内交接、专家执行与等待策略

2026-10-24，SCNet BW/gfx936、DTK wave64 兼容构建，Qwen3.8-F AutoRound INT4，BS=1。
基准提交 a6b66f290e0d6f76862e5da211b523339865789a。增强 MTP 固定 8500 个 GPU 专家；
原生 DFlash2/联合模式固定 8300 个。全部 GPU 模型权重不超过物理显存 50%，PLE 仍在持久盘。
没有更换依赖、量化格式、草稿模型或扫描专家数。

本机增强 MTP 入口默认开启 GPU 独立安排常驻专家、CPU 按专家推进、结果提前交回三项。
其他草稿模式仍显式选择。小批专家搬运、层末休眠默认关闭。
实现与使用见 [说明](../../docs/DCU_LAYER_SCHEDULING.md)。

## 正常测速

每类预热后生成 256 tokens，重复三次，取引擎 decode 时间计算 TPS，排除载入和 prefill。
12 个工作线程加主控线程，CPU 配额 15 核，上下文 512，INT8 KV，增强 MTP adaptive，
HC staged、CPU Q4 多位置计算开启，交换/lookup/PCIe 分流关闭。未加逐层记录。

| 配置 | 英文三次 TPS（中位数） | 中文三次 TPS（中位数） | 代码三次 TPS（中位数） |

| 原二进制 | 33.27, 33.54, 33.25（33.27） | 41.60, 41.23, 40.87（41.23） | 40.63, 37.76, 43.50（40.63） |

基准数据在 `v7/baseline/`，最终数据在 `v9/`，选择结果在 `v9/selection.json`。
样本少且有波动，不声称统计显著或适用于其他机器。仍没有达到外部 R9700 的速度。
v6 为各项单次探索结果，不能替代这里的正式对照。

休眠方案的 12 个工作线程平均占用中位数由约 100% 降至 79.53%；英文/中文/代码分别约
83.2%/79.5%/76.4%。主控线程仍接近 100%。`/proc` 记录包含忙等，不能当作有效计算比例。
其吞吐稍低，所以保留可选。默认没有宣称解决主控线程空转。

小批 DMA 分流使用约 44 MB 锁页中转区，复用原有 16 个 GPU 临时槽，不增加常驻专家。
v6 自适应测试通常只探测约 0.02 个专家/层，没有稳定收益。最终强制搬运最多两个的 QA 确实
发生了接近两个专家/层的搬运（最高报告均值 1.99），全部通过，但不能据此声称加速。

## 逐层执行记录

三份记录分别为 `v9/trace-plain/`、`trace-selected/`、`trace-staged-2/`。
每个已完成窗口均记录全部 48 层，原始日志包括输出头；`layers.csv` 是逐层整理结果。
GPU 和 CPU 时间轴独立，不能跨轴相减，重叠区间不能相加。
记录没有打开会改变融合选择的旧 PROFILE 开关，但时间戳节点和日志仍有开销，不能用于正式 TPS。

## 曾失败并修复的线程交接

首版 CPU 专家队列通过最初 168 次数值检查，但真实预热 SIGSEGV；gdb 捕获在 `ExpertPool::drain`。
原因是新队列没有消耗旧领取计数，晚醒线程可能按结束批次领取不存在的普通任务。
修复在完成时关闭批次，读取执行方式和描述前检查批次编号及是否耗尽。
注入延迟后旧代码 RC139，修复后 RC0、552 次检查通过。
未注入延迟的扩展检查在旧代码上也曾通过，不能用它证明无竞态。
证据：`late-wake-old.log`、`late-wake-fixed.log`、`debug-gdb/stdout.log`。
最终测试日志与早期失败分目录保留。
