# 主控及专家线程 CPU 占用补测

2026-10-24，现有生产二进制 1c5b8a268585ab62bfe53a098c114b7e645c8befa91384d58c645fec9a8ff396。
增强 MTP、HC staged、8500 GPU 专家、12 workers + 主线程、50% GPU 权重上限，PLE 在磁盘。
未改推理源码、二进制、专家位置或线程设置。先预热 128 tokens，再三类任务各三次 256 tokens，最后短请求恢复。
11 个请求均结束，计数及 nonfinite 标记检查通过，进程 QUIT 后退出 0，GPU 回到 2 MiB。
本轮是占用采样，不是新的完整质量评测或优化测速对照。

从 /proc/PID/task/TID/schedstat 读取线程实际调度运行时间，以两次读取之间的墙钟时间计算单逻辑 CPU 占用；
不把整台机器的其他进程计入。decode 边界为读取 REUSED 到读取 DONE，正式请求在预热之后。
边界有协议传递与采样开销；不是 GPU 内部时间戳。另保存 first-token、请求开始快照。
每个正式请求只在边界读取线程信息，无持续高频采样。

| 任务 | 主线程占用中位数 | 12 个 worker 平均占用的三次中位数 |
|---|---:|---:|
| 英文 | 99.68% | 98.05% |
| 中文 | 99.90% | 99.93% |

主线程固定逻辑 CPU 0，worker 固定 1..12。attention 在 GPU，不存在一个专门执行 attention 算术的 CPU 核。
主线程负责提交、轮询 GPU 层通知、安排专家、参与专家任务和输出控制。
源码的轮询及线程池等待会消耗 CPU 调度运行时间，因此上述占用包含忙等，不能解释为有效计算利用率。
未采集指令/函数采样，不能给出主线程有效计算与忙等各自所占比例。
当前容器未发现可执行的 perf 或 pidstat，本次使用内核 /proc 计数。

新增文件：measure.py 为远程原样执行的外部测量脚本；analyze.py 汇总统计；command.json 记录命令及 SHA；
results.json 保存请求、编号和线程快照；analysis.json 保存逐请求及汇总结果；stdout.log/stderr.log 是引擎原始输出。
大文件与远程脚本均放在 /root/private_data/strata-dcu 下，未产生系统盘模型或构建缓存。
