## 正式对照结果

每配置独立冷启动一次，预热128 tokens，三个任务各生成256 tokens、重复三次。
没有并行构建、准备权重或其他GPU任务。decode 排除载入及prefill；只记录主机阶段汇总。
下表为同组测量中位数，prefill单位ms，顺序同英文／中文／代码。

| 配置 | 英文 TPS | 中文 TPS | 代码 TPS | prefill ms |
|---|---:|---:|---:|---|
| baseline | 33.72 | 42.01 | 44.62 | 689.1 / 627.8 / 576.8 |
| q8 | 36.63 | 46.16 | 56.04 | 542.7 / 528.9 / 453.6 |
| q8-tuned | 37.19 | 46.10 | 56.22 | 558.0 / 521.7 / 459.6 |
| hc-q8-tuned | 36.20 | 48.51 | 56.98 | 562.6 / 518.5 / 453.2 |
| q8-tuned-proxy | 36.54 | 48.15 | 56.59 | 565.1 / 525.5 / 504.4 |

选定组合相比基线约提升7.4%／15.5%／27.7%。短提示prefill也下降，但未测长上下文性能。
三次样本不支持统计显著性结论。组合选择规则和实际权重见 final-v1/selection.json、各目录weight-usage.json。
主要改善出现在非专家Q8；蒸馏MTP单独叠加收益有限，HC在英文上也没有稳定增益。
不能把组合收益全部归给某一项。pilot-v1/是探索单次运行，不与正式中位数混合。

## 为什么筛选默认关闭

草稿头先用每32权重一组的两位副本扫描草稿词表，每32行取四个候选，再取全局至多64个，
用原权重重算这些行；其他分数仍近似。主模型照常验证。额外85043200B代理权重已记账。
仅支持单位置、宽度2560的BF16/Q8草稿头；多位置回退完整头。

[生产选项微基准](proxy-kernel-production-flags.log) 中，完整BF16头455μs、筛选570μs；
完整Q8头296μs、筛选563μs。粗算约242μs，候选排序约325μs，原权重重算约8–15μs。
当前DCU上的排序成本抵消了少读权重的收益。早期919μs的BF16参照缺少生产VEC4选项，
不能拿它宣称生产提速。保留原始记录，并以此处生产选项结果为准。
Basalt改编代码标明MIT版权，见 third_party/basalt-head-proxy/LICENSE。

## 后段CPU减速：尚未解决

补充BF16头筛选测试时，CPU专家池每窗口从此前约20ms变成130–325ms；草稿GPU仍是数ms。
同一后段短英文测量：新版原权重关闭筛选8.82TPS、开启8.72TPS；旧生产二进制9.29TPS；
新选定组合9.89TPS。四者smoke QA都通过。
这证明减速也影响旧版，不能据此归因于本轮新功能或据此宣称筛选收益。

cpu-check-*/保存证据。CPU配额仍15、无交换、无OOM。
可选NUMA快照只记录页分布与亲和性，没有证据证明NUMA、宿主争用或温度中的哪一个是原因。
proxy-bf16/也通过18项QA，但它的慢速结果不与之前正式组作性能比较。
上表描述正式测量时段，不能保证机器此刻持续达到相同TPS；该减速原因仍待后续定位。
